# Day 01 — GitHub Professional Setup

**Date:** 2026-09-10

## 🎯 Objective

Set up a professional GitHub profile and establish a public engineering journal for my 12-month transition toward Infrastructure / DevOps Engineering.

## 📚 What I learned

- How GitHub Profile READMEs work
- How to structure a public engineering journal
- The difference between a Git repository and a GitHub Project
- The difference between repository-level and user-level GitHub Projects
- Git working tree, staging area and repository
- The role of `origin` as a remote repository
- How `git status` shows the current repository state
- How `git diff` shows unstaged changes
- How `git diff --staged` shows staged changes
- How to stage specific files with `git add`
- How to remove a file from staging with `git restore --staged`

## 🔨 What I built

- Created and configured my professional GitHub profile
- Created a public Learning Log repository
- Created a reusable daily learning log template
- Created a user-level GitHub Project for my 12-month DevOps journey
- Created my first GitHub Issue and connected it to the project

## 🧠 Problems & solutions

### Problem

I initially assumed that the 12-month roadmap should be managed through a project attached directly to the Learning Log repository.

### Solution

I learned that GitHub Projects can also exist at the user level. Since the 12-month journey will span multiple repositories, I created a user-level project instead.

## 💡 Key takeaway

GitHub is more than a place to store code. It can also provide the infrastructure for documenting work, managing tasks and projects, and presenting a professional engineering portfolio.
